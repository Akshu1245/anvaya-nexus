# HISTORICAL DESIGN MATERIAL — NOT FINAL DEPLOYMENT INSTRUCTIONS

# M7.1 Catalyst Compatibility Foundation

SQLite, prototype authentication, and local artifact storage remain the default ANVAYA runtime. M7.1 introduces only platform-neutral configuration, capabilities, adapter interfaces, and safe placeholders. It creates no Catalyst project, table, user, folder, credential, network request, or deployment.

## Adapter architecture

`platform.factory` selects repository, authentication, artifact-storage, and schema-bootstrap adapters from explicit configuration. SQLite/prototype/local adapters delegate to the existing M0–M6 behavior. Explicit Catalyst selection returns a clearly unavailable placeholder; it never falls back silently to SQLite.

## Configuration

`ANVAYA_STORAGE_BACKEND`, `ANVAYA_AUTH_BACKEND`, and `ANVAYA_ARTIFACT_STORAGE` default to `sqlite`, `prototype`, and `local`. Catalyst switches are opt-in through `ANVAYA_CATALYST_ENABLED` and the related component flags. Production Catalyst selection requires configured project, environment, and API-base placeholders but does not read any credential file.

The authenticated System Health response exposes only capability name, state, and safe detail. It never exposes Catalyst identifiers, credentials, credential paths, tokens, or raw exceptions. Public health remains unchanged.
